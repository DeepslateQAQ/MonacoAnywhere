Nushu subset repair
-------------------
The upstream @kyralabs/m3e-tokens 1.8.0 file for
google-sans-flex-nushu.woff2 (SHA-256
d995ae220224f5970c127ab8989eedd17c6a2007ab9c0d67a08e947504119837)
was rejected by the OpenType Sanitizer used by Chromium:
"ERROR: glyf: zero-length table".

The subset is intentionally two glyphs (.notdef and uni2003); its Nushu
unicode-range falls back for scripts the font does not cover. The upstream
file had a zero-contour .notdef, leaving glyf/loca with no outline data. The
repaired file takes the original .notdef outline (2 contours, advance 1140)
from the same upstream source commit and keeps everything else identical:
same cmap (U+2003), glyph order, name records, fvar axes and metrics. Only
glyf/loca plus table checksums change. OTS now reports
"File sanitized successfully!".
